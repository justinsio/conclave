# Internal development history — not setup documentation

**Nothing in this directory is required to run the seed runtime.** For
requirements and setup, see the repo `README.md`.

These are design specs and implementation plans written *during* the build. They
are kept because the reasoning behind a decision is usually more useful than the
diff that implemented it. They are point-in-time documents:

- They describe the code **as it was when they were written**, not as it is now.
- Some describe work that was later changed, deferred, or cut entirely.
- Commands, absolute paths, and environment notes in them reflect the original
  author's development machine. They are **not** installation instructions, and
  following them will not set anything up.

Read them for context on *why* something is shaped the way it is. Do not read
them as documentation.
